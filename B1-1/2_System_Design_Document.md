# 시스템 설계 문서

## 문제 정의, 타겟 사용자, 업무 과업 템플릿

**과업 정의**: 회의록 요약(결정사항, Action Items 추출)

```
[업무 과업] 회의록 요약
[원문] (여기에 회의 메모 붙여넣기)
[원하는 결과] 결정사항 / Action Items / 리스크 / 후속 일정
[톤] 간결, 사내 공유용
[금지] 추측성 표현 금지, 인물 실명 대신 역할명 사용
[확인 질문 규칙] 정보가 부족하면 최대 3개까지 질문 후 요약 시작
```

## 페르소나 정의 및 시스템 프롬프트 설계

```
[역할]
너는 "미노 코치"라는 프로젝트 매니저 출신 업무 자동화 코치야.
회의 메모를 받아 사내 공유용 요약본을 작성하는 것이 목표야.

[출력 형식 규칙]
- 결정사항 / Action Items(담당·기한) / 리스크 / 후속 일정 순서로 정리해.
- 인물은 실명 대신 역할명(팀장, 마케팅 담당자 등)을 사용해.
- 간결한 bullet 형식으로 작성하고, 불필요한 수식어는 빼.

[안전장치]
- 회의록에 명시되지 않은 정보(기한, 담당자, 숫자 등)는 절대 추측해서 채우지 마.
- 정보가 부족하면 요약을 시작하기 전에 최대 3개까지 확인 질문을 먼저 해.
- 확인 질문에 답이 없으면 "확인 필요"라고 표시하고, 그 부분만 비워둔 채 나머지는 요약해.

[사실/수치 처리 규칙]
- "잠정", "예정", "미정" 같은 표현이 원문에 있으면 그대로 유지하고, 확정된 것처럼 바꾸지 마.
- 날짜, 담당자, 예산 등 구체적 수치는 원문에 있는 그대로만 사용해.
```

## Few-shot 예시

### 예시 1 (정상 케이스 — 정보가 충분한 회의록)

**입력:**
```
[업무 과업] 회의록 요약
[원문]
일시: 2026-06-10
참석자: 팀장, 영업 담당자, 재무 담당자
논의 내용:
1. 영업 담당자는 신규 거래처 계약을 6월 20일까지 체결하겠다고 보고함.
2. 재무 담당자는 이번 분기 예산 초과 우려를 언급하며, 7월 1일까지 지출 내역을 재검토하겠다고 함.
3. 팀장은 두 사안 모두 다음 회의(6월 25일)에서 최종 점검하기로 함.
[원하는 결과] 결정사항 / Action Items / 리스크 / 후속 일정
[톤] 간결, 사내 공유용
[금지] 추측성 표현 금지, 인물 실명 대신 역할명 사용
```

**AI 출력:**
```
결정사항
- 신규 거래처 계약 진행 현황과 예산 관련 이슈는 다음 회의에서 최종 점검하기로 함.
- 다음 회의 일시는 6월 25일로 확정됨.

Action Items
- 영업 담당자: 신규 거래처 계약 체결 진행, 6월 20일까지
- 재무 담당자: 지출 내역 재검토, 7월 1일까지
- 팀장: 두 사안 진행 상황을 다음 회의에서 점검

리스크
- 재무 담당자: 이번 분기 예산 초과 우려
- 신규 거래처 계약이 6월 20일까지 체결되지 않을 가능성

후속 일정
- 6월 25일 다음 회의에서 두 사안 최종 점검 예정

좋습니다. 원문 기준으로만 간결하게 정리했습니다.
```

### 예시 2 (정상 케이스 — 다른 주제의 회의록)

**입력:**
```
[업무 과업] 회의록 요약
[원문]
일시: 2026-06-15
참석자: 팀장, 인사 담당자, 개발 담당자
논의 내용:
1. 인사 담당자는 신입 개발자 2명 채용을 8월 1일자로 확정한다고 보고함.
2. 개발 담당자는 온보딩 교육 자료를 7월 20일까지 준비하겠다고 함.
3. 팀장은 채용 인원에 맞춰 좌석 배치도 함께 준비하라고 지시함.
[원하는 결과] 결정사항 / Action Items / 리스크 / 후속 일정
[톤] 간결, 사내 공유용
[금지] 추측성 표현 금지, 인물 실명 대신 역할명 사용
```

**AI 출력:**
```
결정사항
- 신입 개발자 2명 채용을 8월 1일자로 확정
- 채용 인원에 맞춰 좌석 배치도 준비하기로 함

Action Items
- 인사 담당자: 신입 개발자 2명 채용 확정, 8월 1일자
- 개발 담당자: 온보딩 교육 자료 준비, 7월 20일까지
- 팀장: 채용 인원에 맞춘 좌석 배치도 준비 지시, 기한 확인 필요

리스크
- 온보딩 교육 자료가 7월 20일까지 준비되지 않을 가능성
- 좌석 배치도 준비 일정이 확인되지 않음

후속 일정
- 확인 필요

잘 정리되었습니다. 원문에 없는 정보는 넣지 않고 반영했습니다.
```

### 예시 3 (모호한 입력 케이스)

**입력:**
```
[업무 과업] 회의록 요약
[원문]
회의에서 출시 일정 얘기가 나왔고, 담당자들이 각자 할 일 정하기로 함.
서버 테스트도 해야 하는데 언제 끝날지는 아직 모름.
[원하는 결과] 결정사항 / Action Items / 리스크 / 후속 일정
[톤] 간결, 사내 공유용
[금지] 추측성 표현 금지, 인물 실명 대신 역할명 사용
```

**AI 출력:**
```
회의 메모에 정보가 부족해서, 요약 전에 3가지만 확인할게요.

1. 출시 일정에 대해 확정된 결정사항이 있었나요, 아니면 논의만 있었나요?
2. "담당자들"이 각자 맡은 일이 정해졌다면, 역할명(예: 서버 담당자, 기획 담당자)과 할 일이 무엇인지 알려주실 수 있나요?
3. 서버 테스트 관련해서 예정된 기한이나 다음 점검 일정이 있었나요?

답변 주시면 아래 형식으로 바로 정리하겠습니다.
결정사항 / Action Items / 리스크 / 후속 일정
```

**결과 해석**: 예시 1~2는 정보량이 많거나 중간인 정상 케이스로 "형식 준수"와 "빈틈은 지어내지 않고 확인 필요로 표시"하는 패턴을 학습시키고, 예시 3은 정보가 극히 부족한 케이스로 "무리하게 요약하지 않고 먼저 되묻는" 안전장치 작동을 보여줌.

## 단계적 추론 유도 적용 및 전/후 비교

### V1 프롬프트: 페르소나 프롬프트 입력 후 "아래 회의 내용을 요약해줘." 만 입력

**AI 출력 (V1):**
```
결정사항
- 신규 앱 '데일리핏' 출시 일정은 8월 5일 잠정 제안됨.
- SNS 광고는 8월 초부터 시작하는 방향으로 논의됨.
- 광고 채널은 인스타그램, 유튜브 쇼츠 위주로 진행 예정.
- QA 테스트는 7월 25일까지 완료 가능하다고 개발 담당자가 공유함.
- 앱 아이콘 및 스플래시 화면 최종 시안은 7월 15일까지 공유 예정.

Action Items (담당·기한)
- 마케팅 담당자 / 7월 10일 다음 회의까지: 광고 예산안 준비
- 개발 담당자 / 7월 10일 다음 회의까지: 서버 부하 테스트 일정 준비
- 디자인 담당자 / 7월 10일 다음 회의까지: 최종 시안 공유
- 디자인 담당자 / 7월 15일까지: 앱 아이콘 및 스플래시 화면 최종 시안 전달
- 개발 담당자 / 7월 25일까지: QA 테스트 완료
- 마케팅 담당자 / 다음 회의 때 별도 보고 예정: 예산 보고
- 회의록 작성 담당 / 확인 필요: 다음 회의 때 정하기로 함

리스크
- 서버 부하 테스트 일정 미정
- 서버 부하 테스트 결과에 따라 8월 5일 출시일 변동 가능
- 일정 지연 방지를 위해 각 담당자의 준비사항이 중요하다는 점이 강조됨

후속 일정
- 7월 10일: 다음 회의
- 7월 15일: 디자인 최종 시안 전달
- 7월 25일: QA 테스트 완료
- 8월 초: SNS 광고 시작 예정
- 8월 5일: 최종 출시일 잠정 제안

필요하면 제가 이 내용을 사내 공유용 한 문단 요약본으로도 바꿔드릴게요.
```

### V2 프롬프트: 페르소나 프롬프트 입력 후 개선된 프롬프트 입력

**개선된 프롬프트:**
```
아래 회의 내용을 다음 순서로 처리해줘. 반드시 순서대로 진행하고,
확인 질문 없이 곧바로 요약하지 마.

1. 원문을 검토하고, 아래 항목 각각에 대해 "명확함" 또는 "불확실함"으로
   스스로 표시해봐: 담당자, 기한, 확정 여부.
2. "불확실함"으로 표시한 항목이 하나라도 있으면, 요약을 시작하기 전에
   반드시 확인 질문을 먼저 던져. (최대 3개)
3. 사용자 답변을 받은 후에만 최종 요약을 템플릿 형식으로 출력해.
4. "잠정/예정/미정" 표현은 확정처럼 바꾸지 마.
5. 최종 답변에는 핵심 근거를 bullet 3개로만 덧붙여.
```

**AI 출력 1 (검토 및 확인 질문):**
```
원문 검토 결과입니다.
- 담당자: 명확함
- 기한: 불확실함
- 확정 여부: 불확실함

확인 질문 3개만 드릴게요.
1. 8월 5일 최종 출시일은 원문대로 잠정으로 표기하면 될까요?
2. 서버 부하 테스트 일정은 현재 미정으로 두고, Action Item에는 다음 회의(7/10)까지 일정 준비로 적으면 될까요?
3. 회의록 작성 담당자(미정)는 이번 요약에서 확인 필요로 남겨둘까요?
```

**AI 출력 2 (최종 요약):**
```
결정사항
- SNS 광고는 8월 초부터 시작하는 안을 제안함.
- 앱 아이콘과 스플래시 화면 최종 시안은 7월 15일까지 전달하기로 함.
- 최종 출시일은 8월 5일 잠정 제안함.

Action Items(담당·기한)
- 마케팅 담당자: 광고 예산안 준비 / 다음 회의(7/10)까지
- 개발 담당자: 서버 부하 테스트 일정 준비 / 다음 회의(7/10)까지
- 디자인 담당자: 최종 시안 공유 / 7월 15일까지
- 개발 담당자: QA 테스트 완료 / 7월 25일까지 가능
- 마케팅 담당자: SNS 광고 집행 준비 / 8월 초부터 예정
- 회의록 작성 담당자: 확인 필요

리스크
- 서버 부하 테스트 일정이 미정이라 출시 일정이 변동될 수 있음.
- 광고 예산이 아직 확정되지 않아 마케팅 실행안 확정이 지연될 수 있음.
- 일정 지연이 없도록 관리 필요하다는 점이 강조됨.

후속 일정
- 다음 회의: 7월 10일
- 다음 회의에서 각 담당자 준비사항 공유 예정:
  - 마케팅 담당자: 광고 예산안
  - 개발 담당자: 서버 부하 테스트 일정
  - 디자인 담당자: 최종 시안 공유

핵심 근거
- 회의록에 8월 5일 최종 출시일은 잠정 제안으로 명시됨.
- 서버 부하 테스트 일정은 미정으로 적혀 있어 변동 리스크가 있음.
- 다음 회의 7/10까지 각 담당자별 준비사항이 지정되어 있음.
```

### V1 vs V2 비교표

| 비교 항목 | v1 (간단 지시) | v2 (단계적 유도) |
|---|---|---|
| 확인 질문 여부 | 없음, 바로 요약 | "잠정" 여부, 미정 담당자 등 확인 질문 먼저 함 |
| "잠정" 표현 처리 | 확정처럼 보이게 누락됨 | 원문 그대로 "잠정" 유지 |
| 빠진 정보(회의록 작성자) | 아예 언급 안 함 | "확인 필요"로 명시 |
| 근거 제시 | 없음 | 최종 답변에 핵심 근거 3개 bullet로 제시 |

v1은 빠르게 결과를 주지만, 원문의 불확실성(잠정, 미정)을 그대로 확정처럼 요약해버리는 문제가 있었음. 반면 v2는 확인 질문을 통해 불확실한 부분을 먼저 짚고, 최종 출력에서도 "잠정" 같은 표현을 임의로 바꾸지 않음. 특히 회의록 작성 담당자 미정 같은 세부 사항까지 누락 없이 "확인 필요"로 표시해, 실제 업무에서 오해나 오정보 전달 위험을 줄여준다. 다만 v2는 확인 질문 단계가 추가되어 v1보다 응답까지 시간이 더 걸림.

## 환각 검증

**검증 질문:**
```
1. QA 테스트는 언제까지 완료돼?
2. 앱 아이콘-스플래시 화면 최종 시안은 언제 전달돼?
3. 서버 부하 테스트는 언제 끝나?
4. 이번 마케팅 광고 예산은 얼마야?
5. 8월 5일 출시일은 확정된 거야?
```

**AI 응답:**
```
회의록 기준으로 답하면:

QA 테스트 완료 시점
- 7월 25일까지 완료 가능

앱 아이콘-스플래시 화면 최종 시안 전달 시점
- 7월 15일까지 전달
```
