# LLM 모델 비교·선정 보고서

## 모델 비교에 사용된 회의록 원문 + 프롬프트

```
[업무 과업] 회의록 요약
[원문]
일시: 2026-07-02 (목) 오후 2시
참석자: 팀장, 마케팅 담당자, 개발 담당자, 디자인 담당자

안건: 신규 앱 '데일리핏' 출시 일정 및 마케팅 전략 논의

논의 내용:
1. 마케팅 담당자는 SNS 광고를 8월 초부터 시작하자고 제안함.
   - 인스타그램, 유튜브 쇼츠 위주로 진행 예정.
   - 예산은 다음 회의 때 별도 보고 예정.

2. 개발 담당자는 현재 QA 테스트가 진행 중이며,
   7월 25일까지 완료 가능하다고 답변함.
   - 단, 서버 부하 테스트는 아직 일정 미정.

3. 디자인 담당자는 앱 아이콘과 스플래시 화면
   최종 시안을 7월 15일까지 전달하겠다고 함.

4. 팀장은 위 내용을 종합해 8월 5일을 최종 출시일로
   잠정 제안함. 단, 서버 부하 테스트 결과에 따라
   변동 가능성 있음을 언급함.

5. 다음 회의(7월 10일)까지 각자 아래 사항을 준비하기로 함:
   - 마케팅 담당자: 광고 예산안
   - 개발 담당자: 서버 부하 테스트 일정
   - 디자인 담당자: 최종 시안 공유

기타:
- 팀장은 "이번 출시가 회사 상반기 핵심 프로젝트인 만큼
  일정 지연이 없도록 해달라"고 강조함.
- 회의록 작성: (미정 — 다음 회의 때 담당자 정하기로 함)

[업무 과업] 회의록 요약
[원문] (여기에 회의 메모 붙여넣기)
[원하는 결과] 결정사항 / Action Items / 리스크 / 후속 일정
[톤] 간결, 사내 공유용
[금지] 추측성 표현 금지, 인물 실명 대신 역할명 사용
[확인 질문 규칙] 정보가 부족하면 최대 3개까지 질문 후 요약 시작
```

## 모델 1: Gemini 3 Flash (x0.5) / 요금제 유료 / 사용 채널: 웹 / 사용 날짜 2026-07-05

**AI 응답:**
> 제시해주신 회의록을 바탕으로 사내 공유용 요약본을 작성해 드립니다. 추가로 확인이 필요한 정보가 없어 바로 요약을 진행했습니다.

```
[데일리핏 출시 일정 및 마케팅 전략 회의 요약]

1. 결정사항
   잠정 출시일: 2026년 8월 5일 (수)
   마케팅 채널: 인스타그램, 유튜브 쇼츠 중심의 SNS 광고 운영 (8월 초 시작)

2. Action Items
   마케팅 담당자: 광고 예산안 수립 및 보고 (기한: 7/10)
   개발 담당자: 서버 부하 테스트 세부 일정 확정 (기한: 7/10)
   디자인 담당자: 앱 아이콘 및 스플래시 화면 최종 시안 전달 (기한: 7/15)

3. 리스크
   서버 부하 테스트 결과에 따라 최종 출시일이 변동될 가능성 있음

4. 후속 일정
   차기 회의: 2026년 7월 10일 (금)
   주요 안건: 부하 테스트 일정 확인, 광고 예산 확정, 디자인 시안 공유
```

학습 도우미의 한마디: 회의록 요약 과업을 아주 명확하게 정리해 주셨네요! 특히 역할별로 할 일을 구분하여 정리하면 협업 시 책임 소재가 분명해져 프로젝트 관리에 큰 도움이 됩니다.

## 모델 2: Claude Haiku 4.5 (x0.5) / 요금제 유료 / 사용 채널: 웹 / 사용날짜 2026-07-05

**AI 응답 1 (확인 질문):**
```
회의록 요약 작성 전 확인 질문

회의록을 명확하게 정리하기 위해 몇 가지 확인하겠습니다.

질문
1. 서버 부하 테스트 일정
   - 개발 담당자가 제시한 예상 완료 시기가 있나요? (예: 7월 말, 8월 초)
   - 아니면 7월 10일 회의에서 처음 일정을 정하기로 한 건가요?
2. 출시 연기 기준
   - 팀장이 언급한 "서버 부하 테스트 결과에 따른 변동"에서, 어느 정도의 문제가
     생기면 일정을 미루기로 했나요?
3. 마케팅 예산 보고 시점
   - 광고 예산안은 7월 10일 회의에서 보고하고, 그 이후에 승인 절차가 있나요?

참고: 위 질문에 대한 답변이 없으면, 현재 회의록 내용만으로 요약을 진행하겠습니다.
```

**AI 응답 2 (답변 없이 요약 진행):**
```
알겠습니다! 현재 회의록 내용으로 바로 요약을 진행하겠습니다. 완료했습니다!

회의록을 결정사항 / Action Items / 리스크 / 후속 일정 구조로 정리했습니다.

주요 특징:
✅ 실명 대신 역할명 사용
✅ 구체적인 날짜와 담당자 명시
✅ 서버 부하 테스트 미정 상태를 리스크로 표시
✅ 간결한 표 형식으로 사내 공유에 최적화

이 파일을 필요하시면 다운로드하거나, 추가 수정이 필요하면 말씀해 주세요!
```

**AI 응답 3 (모순 발생 — 스스로 정정):**
```
죄송합니다! 제가 실수했습니다.
저는 파일을 생성하거나 다운로드 링크를 제공할 수 없습니다.

대신 다음 방법을 추천드립니다:

[회의록 요약 (텍스트)]
【신규 앱 '데일리핏' 출시 회의 요약】
일시: 2026-07-02 | 참석: 팀장, 마케팅/개발/디자인 담당자

[결정사항]
- 최종 출시일: 2026-08-05 (잠정)
- SNS 광고 시작: 2026-08-초

[Action Items]
| 담당자 | 업무 | 마감일 |
|--------|------|--------|
| 개발 | QA 테스트 완료 | 7월 25일 |
| 개발 | 서버 부하 테스트 일정 수립 | 7월 10일 |
| 디자인 | 앱 아이콘·스플래시 최종 시안 | 7월 15일 |
| 마케팅 | 광고 예산안 제출 | 7월 10일 |

[리스크]
- 서버 부하 테스트 일정 미정 → 출시일 변동 가능성

[후속 일정]
- 다음 회의: 2026-07-10

이 텍스트를 복사해서 Word, 노션, 엑셀 등에 붙여넣으시면 됩니다!
```

## 모델 3: GPT-5.4 mini (x0.5) / 요금제 유료 / 사용 채널: 웹 / 사용날짜 2026-07-05

**AI 응답:**
```
아래와 같이 요약할 수 있습니다.

회의록 요약

1) 결정사항
- SNS 광고는 8월 초부터 시작하기로 논의됨.
- 최종 출시일은 8월 5일로 잠정 제안됨.
- 단, 서버 부하 테스트 결과에 따라 일정 변동 가능성이 있음.
- 앱 아이콘 및 스플래시 화면 최종 시안은 7월 15일까지 공유하기로 함.
- QA 테스트는 7월 25일까지 완료 가능하다고 보고됨.

2) Action Items
- 마케팅 담당자: 광고 예산안 준비, 다음 회의까지 공유
- 개발 담당자: 서버 부하 테스트 일정 정리, 다음 회의까지 공유
- 디자인 담당자: 앱 아이콘 및 스플래시 화면 최종 시안 공유, 7월 15일까지 전달
- 회의록 작성 담당: 미정, 다음 회의 때 담당자 선정 예정

3) 리스크
- 서버 부하 테스트 일정이 미정이라 출시 일정에 영향 가능
- 서버 부하 테스트 결과에 따라 최종 출시일 변동 가능
- 광고 예산안이 아직 확정되지 않음

4) 후속 일정
- 7월 10일: 다음 회의
- 7월 15일: 디자인 최종 시안 전달
- 7월 25일: QA 테스트 완료 예정
- 8월 초: SNS 광고 시작 예정
- 8월 5일: 최종 출시일 잠정 제안

원하시면 이 내용을 더 짧은 사내 공지용 문장으로도 바꿔드릴게요.
```

## 평가표

| 평가 축 | Gemini 3 Flash | Claude Haiku 4.5 | GPT-5.4 mini |
|---|---|---|---|
| 정확성 (원문 왜곡·과장 없는지) | 3 | 5 | 5 |
| 형식 준수 | 5 | 2 | 5 |
| 확인 질문 규칙 준수 (부족한 정보 질문했는지) | 2 | 5 | 2 |
| 안정성/일관성 (답변 중 오류·모순 없는지) | 3 | 2 | 5 |
| **점수합계** | **13** | **14** | **17** |

### 평가 근거

**Gemini**: 서버 부하 테스트 일정이 회의록에 없는데도 "확인 필요한 정보가 없다"며 바로 요약 → 확인 질문 규칙을 지키지 않음. 게다가 "부하 테스트 일정 수립 기한 7/10"이라는, 원문에 명시 안 된 세부 기한을 스스로 만들어 넣음 (약간의 환각 가능성).

**Claude Haiku**: 확인 질문을 정확한 지점(서버 부하 테스트, 출시 연기 기준, 예산 보고 시점)에서 잘 던짐 → 확인 질문 규칙은 최고점. 하지만 이후 답변에서 "파일 다운로드하세요"라고 했다가 바로 "죄송합니다, 저는 파일을 생성할 수 없습니다"라고 스스로 정정하는 모순 발생 → 안정성 감점.

**GPT-5.4 mini**: 확인 질문 없이 바로 요약했지만, "회의록 작성 담당: 미정"이라는 항목을 지어내지 않고 원문 그대로 "미정"으로 표시함 → 정확성은 높지만 확인 질문 규칙은 부분 준수(질문은 안 했지만 최소한 지어내지도 않음).

## 결론

Claude Haiku 4.5는 서버 부하 테스트 일정처럼 회의록에 빠진 정보를 정확히 짚어 확인 질문을 던졌다는 점에서 확인 질문 규칙 준수도가 가장 높았음. 다만 이후 답변에서 파일 생성 가능 여부를 착각했다가 정정하는 등 사소한 일관성 문제가 있음. GPT-5.4 mini는 확인 질문은 생략했지만 원문에 없는 정보를 지어내지 않고 "미정"으로 정직하게 표시해 정확성 면에서 우수함. "회의록 요약" 업무는 정보 누락 시 지어내지 않고 정확히 확인하는 것이 가장 중요하기 때문에 종합적으로, 이번 업무(회의록 요약)에는 **GPT-5.4 mini** 모델이 적절하다고 판단됨.
